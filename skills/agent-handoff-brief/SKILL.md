# 任务交接简报

面向真正会接手任务的人或代理。先读用户最后确认的目标、范围和交付约束，再找最近一次有证据的运行或修改。旧的方案讨论只保留仍影响决策的部分。

选出接手者最需要的六项内容：

| 信息 | 写法 |
| --- | --- |
| 目标和完成条件 | 用户要拿到的具体结果，以及如何确定完成 |
| 当前状态 | 已交付、进行中和受阻事项分开写 |
| 工作位置 | 用户允许共享的相对路径、文档标题或链接 |
| 关键决定 | 选择了什么、依据是什么、何时需要重审 |
| 验证边界 | 最近执行的命令或手工检查、实际结果、未覆盖情形 |
| 下一步 | 指向一个可执行动作，以及应观察到什么结果 |

只在消息里要求摘要时直接交付文本；指定文件交接时按指定位置写入。已有详细设计、提交或测试报告时给出定位，避免拷贝整段聊天。涉及失败重试时写明哪些动作已经发生、哪些还有副作用，收件人据此决定能否安全继续。

发送前做一次“陌生接手”检查：只拿这份简报能找到产物吗？能区分评审建议与已经落实的改动吗？能判断第一步成功了吗？隐藏令牌、私人联系方式、个人电脑绝对路径及与任务无关的对话内容。
