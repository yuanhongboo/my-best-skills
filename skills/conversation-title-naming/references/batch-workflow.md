# 历史整理与核验

## 覆盖范围与快照

- 先发现当前宿主的列表、读取和标题修改工具，核实各来源与归档操作的支持情况。Codex 工具可能列出 ChatGPT 对话，但不代表同一标题工具能够修改它们。
- 列表可能有数量上限、分页、独立置顶区和独立归档列表。遍历提供的游标，按宿主与对话 ID 去重并记录覆盖数量；不要把第一页当作全部历史。无法完整枚举的来源明确说明覆盖范围。
- 默认整理用户可管理的对话，包括授权范围内的自动任务与归档对话；排除内部子代理和审批记录。分类字段不足时核实宿主语义，不固定本次观察的来源白名单。
- 列表缺少日期或历史覆盖时，可只读检查宿主元数据及原始会话文件。从当前配置或 `CODEX_HOME` 发现路径，未设置时使用用户主目录下 `.codex`；先查看当前 schema。不要硬编码机器用户名、数据库版本、旧会话 ID 或本次任务目录。
- 修改前保存目标 ID、原标题、日期证据和可用保护字段，另存项目与侧边栏排序快照。工作记录使用本次独立临时目录，不写入无关项目。

## 计划与执行

- 每个目标记录期望标题或保留原名及原因。模糊项读取实际请求和后续处理；可并行分类互不重叠的目标，由主执行者统一相同周期任务的常规主题。实际转入故障修复等新主线的个案保留具体主题。
- 日期、分类和范围确定后检查计划，再使用宿主标题工具执行。修改前若发现原标题已被其他操作更改，重新核对该条，不覆盖并发修改。
- 先用一个自然目标检查工具是否会改变排序或归档等保护字段；出现副作用时停止批量执行并查明。使用有界批次，记录每条工具结果；失败不阻塞不受影响的目标。
- 不把一次归档失败写成永久“不支持归档”的结论，每次重新发现能力。同一来源或状态持续出现相同缺失能力错误时记录该组无法执行，避免无限重试。不要通过取消归档、移动项目、发送消息、直接写宿主数据库或改写会话文件绕过标题工具限制。
- 区分待执行、已尝试、已回读核验、原样保留、内容不明、无能力及失败状态。工具成功返回只证明调用结果，完成状态还需要宿主回读确认。

## 回读与报告

- 每个目标核对实际标题；成功项应等于期望标题，未执行和失败项应保持原标题。检查类型、上海日期和主题规则。
- 对比项目名、归属、显式排序、置顶、归档和可用内容证据；普通列表、置顶区及归档列表分别复核。当前运行会话的更新时间、用量可能自然增长，单独记录；不要把所有会话的更新时间变化排除，更不能忽略实际排序变化。
- 报告实际改名并核验数、内容不足保留数、工具失败或无能力数及未覆盖来源。只声明实际验证的不变项，无法验证的字段注明限制；明细区分期望标题与已修改标题。截图不能代替逐条回读和状态比较。

## 离线校验格式

脚本输入需从真实宿主记录归一化；它不会获取或证实来源。`id` 使用跨宿主唯一的稳定标识；创建时间无法确定时用 `null`，该条只能保留原名。

`before.json` 与 `after.json`：

```json
{
  "threads": [{
    "id": "local:example", "title": "排查登录异常",
    "created_at": "2026-01-01T16:05:00Z", "project_id": "project-a",
    "position": 3, "pinned": false, "archived": false
  }],
  "projects": [{"id": "project-a", "name": "示例项目"}],
  "sections": [{"id": "tasks", "thread_ids": ["local:example"]}]
}
```

必须真实取得 `project_id`、`position`、`pinned`、`archived`，不能用臆造默认值补齐。可增加置顶顺序、内容指纹等字段；除了 `title`，其他字段均要求不变。所有数组保留来源顺序，包括 `threads`。不要加入与保护条件无关且持续变化的运行计数。

`plan.json` 包含所有快照目标，`new_title: null` 表示保留原名：

```json
[{"id": "local:example", "new_title": "0102|修复|登录异常", "reason": "真实请求与故障处理记录"}]
```

执行失败或无修改能力的条目，在**核验计划**中设为 `null` 并注明原因；原始期望计划及工具结果另行保留。`verify` 比较核验计划，不会把计划保留算作已改名。返回 `ok` 只说明输入快照通过所列检查，不能证明源数据完整、主题准确或真实执行过工具。
