# HyperFrames 视频制作

确认本次交付物。如果用户只要选题、文案、字幕或封面，完成相应阶段即可。整片制作需要主题来源、受众、画幅、目标时长和旁白选择。尊重已确认的脚本节点及用户明确指定的发布权限。

## 从素材到分镜

将主题压成一个观众看完能回答的问题。用“口播／画面变化／依据”三列编排：说到结果时让结果出现在画面里，说到操作时展示实际动作。把脚本与制作指令分开保存，以免配音读出舞台提示。无法证实的经历和数据留作待核，或改成明确标注的演示情形。

## 对齐音轨与画面

按已确认旁白逐段合成或录音，复用用户指定声音。先试听，再测量实际秒数；目标长度与听感冲突时优先调整停顿或商定删改。修改旁白后，重新量时并更新字幕与切点。项目已有时间线时沿用其格式；没有时用 [时间表脚本](scripts/plan_frames.py) 把实测时长和段后停顿换算成连续帧区间。格式见 [时间与验收](references/media-checks.md)。

## 制作与验收

1. 从已安装的 HyperFrames 项目模板开始。在目标项目内使用其本地 `hyperframes` CLI；先查看 `hyperframes --help` 确认当前版本的生成、检查和渲染入口。模板生成的 `index.html` 是编辑入口。片段长度和开始时间以测得的帧区间为准。
2. 将宽高、帧率和片长记入本次制作规格。不同画幅各自安排字级、留白和动作；在同一套素材上派生时记录来源。封面用第一帧截图检查标题是否完整，单独核对每个画幅的像素。严禁用网页视口截图代替对最终成片的检查。
3. 先 lint 并预览首帧、转场前后和末帧，再渲染正式媒体。在支持下列命令的版本中，从项目根运行 `hyperframes lint .` 和 `hyperframes render -o clip.mp4`。用 FFprobe 的实际流信息检查成片声轨、分辨率、帧率和时长。视觉可以定点抽查，听感需要试听。
4. 交付用户选择的产物，说明对应规格和还待确认的素材。在发布态交付时核对字幕、封面、署名、内部占位和授权；仅在获得发布授权后执行平台动作。
