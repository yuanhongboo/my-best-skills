# 工程稿发布编辑

输入包括原始事实或草稿、读者、目标载体，以及可选的作者样稿。交付物可以是发布稿，也可以是对现稿的编辑意见。发布稿能直接交给读者；内部事实核对、待授权素材等说明放在单独的交付备注里。

## 定立文章角度

从材料里列出“读者已经知道什么”“这次能多判断什么”“哪项证据使结论成立”。例如，一个兼容性修复的文章可以从用户打开旧文件看到的异常写起，再追踪读入路径，最后解释升级后哪些文件需要重建。若材料只有产品说明，按资料解读写作；实验、作者体验与读者反馈各用其自身证据。

## 按作者与载体编辑

- 有样稿时抽取可观察的偏好，如术语保留、段落长度和引入数据的方式。用当前作者提供的材料表达当前观点，避免复制样稿特色段落或替作者补经历。
- 长文以一个可验证的主张贯穿。例子引入机制，机制解释观察值，取舍说明条件。删掉不影响主张的功能清单。
- 短帖从可单独成立的观察开篇。保留决定性的条件和出处，把复杂比较放进同一口径的一小组数字或一张例图。用户要求线程时才拆成多条，并保证第一条就能读懂主题。
- 质量审查单列会影响发布的问题：来源不支撑结论、把推测写成亲历、截图露出内部信息、首段未交代事件、结尾重述开头。标清原稿位置及修改建议。

最后把正文当成第一次见到它的读者来读。检查链接文字是否能说明证据、图注是否能独立解释口径、相关术语前后是否一致。外部发布遵循用户明确选择的渠道和授权。
