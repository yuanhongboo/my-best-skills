# 中文技术稿局部审校

先划定可改的文本和交付方式。用户问“哪些句子生硬”时，摘出原句并解释阅读障碍；明确要求精修时，直接返回改后的文本。用户提供的术语表、引语、代码、指标口径和作者立场构成约束。

逐段确认主语、动作和依据。优先处理下面三类实际问题：

- **读者找不到对象。** “这进一步降低了它的开销”可能指缓存或队列。若上下文能确定，补回准确主语；若确定不了，圈出歧义，保留原意待核。
- **句子做了多余的工作。** “需要特别强调的是，日志会在断开连接后保留”可以直接写“断开连接后仍保留日志”。删掉开场不会改变事实，句子的重点更容易找到。
- **改写可能扩大主张。** “这次在单机复现中延迟下降”不能改成“该设计降低延迟”。保留测试条件、估算标记、完成时态和因果强度。

一处疑似模板句只有造成具体问题时才动。命令输出、接口名和需要精确讨论的原话保持原样。结构性缺口可单独留一条简短意见；局部精修通常无需改标题、重排章节或扩充案例。

交付前逐句对照原稿，检查数字与单位、主体、肯定或否定方向、时间范围和引述归属。审阅模式只列有依据的问题；改稿模式按用户指定的完整稿或差异格式输出。
