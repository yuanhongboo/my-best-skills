# 职位扫描日报

输入是业务日期、目标岗位与可接受条件、允许使用的来源，以及可选的上期报告。一次性请求也可以只处理用户提供的一组职位链接。建立一个简短的来源表，记录本轮计划读取什么、实际读取了什么、遇到了什么限制。

## 判断是否出现新机会

1. 给每个职位分配稳定标识。优先用雇主加招聘编号；缺少编号时使用雇主、岗位和地点的组合，并保存职位链接。链接中的推广参数不作为新岗位的依据。
2. 在官方职位详情或招聘系统上核对是否仍开放、地点、用工方式和与筛选条件有关的要求。搜索摘要只能成为线索。用“截至何时”“据哪个来源”限定结论。网页未加载、拒绝访问和明确关闭分别记录。
3. 对照上期。新增且满足条件的列在首屏；继续有效的放入复核表。降级需要写清哪项条件发生了变化，移除需要关闭或不再合格的证据。未复核的条目标为“本期待核”。
4. 结果为空时先看来源表。部分来源失败，只报告成功覆盖部分的结果。关键来源均失败，报告本轮覆盖不足并列出失败来源；成功完成全部计划且没有新匹配时，可以写“已覆盖来源中无新匹配”。

## 日报与通知

正文依次给出业务日期与覆盖、建议采取的动作、变化、仍待核实的线索。每个可行动的职位附详情依据、核验日期和一个短理由。需要核对前后两期差异时，可使用 [稳定标识比对脚本](scripts/compare_listings.py)。输入格式和样例见 [差异表](references/listings.md)。

只生成日报时，到报告和自检结果为止。调度、通知、重发按照用户选择的部署流程执行。队列收到了任务就记录“已入队”；有对应日期和消息的服务商回执后再记录“已接受”。送达与阅读是不同状态。
