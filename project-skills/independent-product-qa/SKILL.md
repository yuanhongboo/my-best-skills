# 独立产品巡检

先从用户指定路径、当前规范或可确认的不变量选择检查目标。将任务范围、被测版本、数据初态、环境和检查者写进同一份报告。纯只读任务用现有环境与证据，报告可直接在对话中给出。真实付费请求、外发消息和持久业务写入沿用用户已有授权。

1. **运行线。** 从产品正式入口重现用户动作。记下进入前状态、实际结果与关键中间观察。采集与判断相关的尺寸、时间或截图，固定比较条件。性能样本写明冷启动或热启动、样本数和并行负载。
2. **源码线。** 核对相应入口、状态所有者和实现分支，用源码推导一个能区分原因的反例。说明是否使用替身、旧构建或已有运行服务，并核实服务的版本。
3. **交叉复核。** 用反例回到正式入口。对偶发现象保留运行次数及失败样本。修复超出本轮范围时，保留问题和验证步骤；已有修复授权时，沿用原问题和同一条件复测。
4. **收尾。** 汇总发现、通过的路径、未覆盖范围和核验限制。隔离资源以创建者负责收尾，保持原用户数据。查不清现象或影响时写“待确认”与下一条最便宜的判别检查。

单条记录可按“初态与动作 / 预期依据 / 实际结果 / 版本与复现频次 / 影响 / 证据和缺口”组织。例如仅在未保存的新文档中复现列表错序，就写出“未保存”这个必要前提并复测一个已保存样本。独立核验需记录真实检查者身份与所见输入；同一作者的第二次自检仍记为自检。
