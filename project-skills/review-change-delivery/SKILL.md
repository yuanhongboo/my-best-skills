# 拉取请求交付

先确认上游仓库、源分支、目标分支和用户要求的动作。仅准备说明可直接交付文字。已有创建、更新或合并授权时，使用宿主可用的仓库接口完成对应动作并回读。工作树中的未提交修改不用为创建现有分支的拉取请求而暂存。

**准备候选。** 读取提交图、任务基线及源/目标间实际差异。查远端已有请求及其源分支，避免重复建立。找不到共同祖先时，核查是否选错仓库或目标；不要为了制作请求自动接合无关历史。按库内约定起标题，正文提供问题、可观察的改动、验证结果和已知缺口。引用真实执行过的检查。

**发起或更新。** 准确识别本地和远端源分支的版本。若发布还需要额外操作，则按本次授权范围处理。完成后回读源与目标、最新版本以及草稿或开放状态。遇到网络超时先查已存在的结果，再决定是否重试。

**合并。** 在即将合并时重新核对用户指定请求和可合并版本、所需检查、审阅结果、冲突和分支策略。检查挂起与没有配置检查是两种状态。分支在检查后增加提交时，核对新版本的门槛；宿主支持匹配预期版本时使用该条件。使用仓库允许且符合请求的合并方式。未获授权时，保留源分支、发布和部署给各自流程。

最终报告实际执行的动作、源与目标、已远端核实的状态及尚缺的检查；若动作回执含糊，用只读查询复核后再报告。
