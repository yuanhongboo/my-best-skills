# 文档编辑与历史

先画出一次用户操作的写入路线：草稿由谁持有，哪个公开操作提交，哪份文档是权威状态，历史栈归属文档、视图还是会话。找到当前版本的读取、提交、撤销和重做入口。快照若只是派生数据，验证时通过公开领域操作重新读取状态。

按实际合同选以下序列。记录提交前后的文档内容、修订、撤销/重做可用性及确实可见的通知。只有项目要求引用稳定时才核对对象身份。

| 条件 | 操作与判据 |
| --- | --- |
| 一个动作改变多个字段 | 从正式入口提交整批修改。若承诺原子提交，制造第二项失败，确认没有第一项残留、历史指针也未移动 |
| 正常回放 | 提交、撤销、重做，比较三个状态与必要的资源依赖。尝试在撤销后做新修改，按当前合同核对原重做分支的去向 |
| 回放遇到冲突 | 在合适的测试环境制造过期修订或资源冲突。观察文档和指针；解除冲突后重试原操作，确认同一条记录仍可用 |
| 连续编辑分组 | 在一组内连续编辑后结束组，再做单独操作。两次撤销应分别对应独立操作与整组；同时核查过期组或跨所有者提交的合同 |
| 监听器抛错 | 分开读取提交结果和监听器回执。如果提交已成功，先核对真实状态，再判断通知补偿；盲目重试可能重复写入 |

输出应能回答哪一层成功或失败、外部效果是否可回滚，以及在当前验证中尚未覆盖的持久化和跨进程行为。若系统允许部分提交，把实际边界写清，并针对其承诺设计复验。
