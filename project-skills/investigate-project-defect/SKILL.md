# 产品故障诊断

从报告中提取可观察的现象、必要初态、触发动作、预期来源和实际结果。截图支持对当时画面的判断；涉及时间、状态持久化或后续动作的结论，要有相应的记录。来源不清的期望先查产品合同与相邻行为。

1. 固定与失败有关的输入和版本，找出最早偏离预期的一次状态变化。沿公开入口检查读取、计算、提交和展示各自发生了什么。需要复现时使用用户请求范围内的一般产品操作与隔离测试数据。
2. 给每个候选原因写出可区分它的预测，优先做最少扰动的一项检查。例如保存后表格仍显示旧值，分别读取已保存值和刷新后的列表：保存结果正确而只刷新后显示正确，才有理由进一步检查列表失效逻辑。
3. 保留能推翻自己假设的样本。检查结果如果同时兼容多个解释，记录“尚未区分”和下一项可判别的观察。多次执行时，先比对输入版本、发起方与覆盖范围，同一命令运行两次可能是修复后的必要复验。
4. 诊断任务给出原因、依据、影响和最小改动建议。用户授权修复时，在持有错误状态的层修正，重放原失败路径，并检查共享该机制的一项相邻行为。未知结果先核实实际状态，避免重复提交。

报告保留一段完整因果链，分别标明已观察、已排除和未验证的部分。缩小诊断范围时写明前提，使其他维护者可以用相同条件重新判断。
