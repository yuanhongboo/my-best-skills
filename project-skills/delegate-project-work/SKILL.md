# 派发和决策

先选可独立交付的切片。共享写入、紧耦合状态或单个有状态运行环境归一个负责人；适合并行的是有清楚输入输出的切片，以及有限范围的只读核查。小任务按宿主和项目约定直接处理。

给每个执行者这份简报：目标和结束条件、必须读取的输入及版本、已确定接口、允许写入的范围、其他人持有的资源、应返回的证据以及用户尚需决定的事项。已授权实施的执行者可以直接完成约定步骤。项目要求主代理派发时，在实施简报中指明谁实际动手，避免相同要求在子代理中递归展开。

**决定是否打断用户。** 可查事实先查原文件、调用点或运行证据。多个可逆实现都满足现有合同，选更符合本项目的方案并说明取舍。涉及未确定的产品效果、对外承诺或新增授权时，带一条推荐、可见代价和卡住的步骤向用户询问；与决定无关的部分继续。对复杂技术判断可安排独立核查并复核依据。检查者的偏好本身不能重写既定需求。

**交接和验收。** 回传应指出实际完成范围、产物位置、执行过的检查、发现的反例和缺口。负责人核对目标版本、差异以及关键路径。多个检查者协作时，指定谁操作浏览器或其他有状态资源。需要独立复核时，选择未创作被审内容的检查者并提供原始材料。记录模型选择来源及能观察到的实际值，按用户要求选用指定模型；模型名不同本身不构成独立审查。

例：一人修改列表过滤条件，一人验证键盘操作。如果两人共用同一预览会话，先交接数据条件和焦点状态，再由验证者独占操作；两人各自看到一次正确截图无法证明同一状态可以复现。
