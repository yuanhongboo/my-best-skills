# 规格变更工作流

先确定用户要处理的变更、当前阶段、交付终点，以及仓库维护现行规格和活跃变更的位置。读对应的项目约定、已经存在的输入及其版本。名称相近的多个变更若会导致写入不同目录，先消除歧义。只有单项检查的任务可以直接以用户给定的范围和基线开始。

- 新需求、需求澄清、技术设计、任务拆分或实现，按[阶段与输入](references/stages.md)选择本轮入口。
- 已开始的变更发生调整、换人、重试或准备归档，按[变更与恢复](references/lifecycle.md)核对影响。
- 验收、单项测试或独立代码审查，按[核验证据](references/verification.md)选择与风险匹配的检查。

授权执行阶段变更时，把结论写入项目已有的规格、任务或验收记录。只问条件或要求只读审查时，在回复中给出结论、证据和缺口。项目使用规格管理 CLI 时，先查其已安装版本的帮助、当前依赖图及结构校验结果。仓库没有对应机制时可直接提供阶段所需内容；一次局部分析无需安装框架。

单独指定阶段时交付该阶段的结果。用户已授权完整实施时，连续完成相关输入准备、实现和必要验收。每次报告清楚当前产物的用途、尚缺的输入以及可复用的证据。
