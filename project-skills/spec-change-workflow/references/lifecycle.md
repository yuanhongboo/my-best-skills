# 变更、接手和归档

**需求变化。** 找出具体改变的断言、受影响消费者和已完成验证。先在规范正本调整目标，更新直接消费它的设计、任务和受影响的验收项。只使依赖失效输入的证据过期。需求尚有分歧时，分别记录既有约定、当前实现和待确认的变更。

**接续工作。** 定位原工作区、输入版本、已有差异和未关闭操作。确认同一文件仍有谁在写。对返回状态未知的操作先查回执，再判断能否重试。接替者读取原始输入及结果，复用适用版本的证据，从首个缺口继续。换模型时区分各阶段作者、检查者与可观察的执行配置。

**归档。** 查实际任务完成情况、必需检查及其版本。保留失败、免除原因和仍待用户决策的项目。仅在项目要求满足并有归档范围时，使用其既有入口合并变更规格并归档活跃记录，然后重新核对主规格、变更位置与回执。若已归档，先找到历史定位及后来变更，避免再次合并。中止或暂停的变更按项目约定保留状态。

归档报告写明规格是否已合入、工程验证结果、是否需要用户验收及实际外部交付状态。归档后如发现真实回归，引用原变更与失败版本，按新的修复范围处理。
