# 核验证据

用一行描述被验对象、输入版本、实现版本与本次验收范围，再逐项记录“来源 → 可观察结果 → 实际执行与证据 → 结论”。缺少测试环境或尚未运行时，记录受影响的条目，并继续覆盖能检查的部分。

- **只测试。** 选已确定的场景和当前公开入口；检查成功、关键失败以及状态不应改变的地方。测试回执写明运行对象与断言覆盖。不要因发现规格疑问而悄悄改写预期。
- **只审查。** 对照基线阅读差异、调用者与已有断言。发现应包含触发条件、实际错误结果和定位；不为完成审查自动修码。要求独立审查时，检查者须未参与被审内容创作，并直接读原始输入与版本。
- **综合验收。** 分别呈现规范符合性、工程检查、用户路径和必要的非作者审查。涉及公开合同、状态所有权、兼容策略或用户可观察行为的关键变更，按项目要求在下游消费或最终验收前完成独立核验。
- **有 UI 的复验。** 使用相同数据、主题、尺寸及状态对照预期与实际。保留能定位差异的证据。例如弹窗已开发但焦点恢复行为未在运行中检查，应分别记录布局和键盘路径的结果。
- **修复后。** 核实失效的检查和新引入的影响，复验这些部分。同一版本的其他有效回执可按覆盖范围继续使用。结构校验、任务勾选、打包成功、用户接受和外部发布各自需要对应证据。
